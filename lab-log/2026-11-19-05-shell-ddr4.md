# 2026-11-19 — 05_shell: both DDR4 channels pass, personas swap over PCIe

> Status: verified
> Source: measured on this card
> Last verified: 2026-11-19

- **Date:** 2026-11-19
- **Board:** Microsoft FPGA 1768 (Catapult v3 Longs Peak), PCB `M1003380-005`
- **Host:** ASUS X99-E, BIOS 1801, Above 4G Decoding on, card in `PCIEX16_2` (x8),
  Windows 10 Pro 19045. Card cooling: passive copper heatsink plus a small fan, card
  power from the slot only.
- **Toolchain:** Quartus Prime Pro 25.1.0 Build 129, patches 0.36; on-board FT232H
  (community plugin, 5 MHz TCK); `host/build/fpga1768.exe` built from `host/`.
- **Goal:** bring up `projects/05_shell` on hardware — PCIe Gen3 x8 endpoint, both DDR4
  channels, the DDR test personas — and take the flash backup required before any future
  flash work.

## What was done

1. Simulation and timing closure were done before the hardware session; both modes pass
   and both builds meet timing. Details in
   [projects/05_shell/README.md](../../projects/05_shell/README.md).
2. Three AC power cycles were needed during the day: the first cold boot left the FT232H
   absent, the second brought it back and allowed the shell to be loaded (that run then
   shut down on temperature), and the third was made after a fan was fitted. The FT232H
   needs a full power removal, and so does the card after a thermal shutdown.
3. Loaded `shell.sof` over JTAG (volatile only):
   `quartus_pgm -m jtag -o "p;projects/05_shell/output_files/shell.sof"`.
   `Device 1 contains JTAG ID code 0x02E060DD`, checksum `0x30939483`, 08:16 at 5 MHz.
4. Warm reboot (`shutdown /r`) so the BIOS assigns the 64-bit BAR at boot.
5. `fpga1768 info` and `fpga1768 ddr status`.
6. Walking-one persona, top channel: short range with address test, mailbox write/read,
   inverted pattern over 36 MiB, then the full 2304 MiB.
7. Swapped to `persona_prbs` over PCIe (`load-pr`) and repeated the full test, both
   channels, PRBS-31 with seed `0x1234`.
8. Two 128 MB `flash-dump` runs, compared by SHA-256.
9. `quartus_pow` on the fitted design to explain the die temperature.

## Observations

### Enumeration

The FPGA kept its configuration across the warm reboot and Windows assigned the 64-bit
prefetchable BAR:

```
Device:  1172:E003  "PCIe BAR0 Test Endpoint"
BAR0:    0x383FFFE00000 length 0x10000
Link:    Gen3 x8
ID:      0x50434945
A:       0x53480501
COUNTER: 0x268BBD2E -> 0x268BBE92 (changing)
```

### DDR4, walking-one persona

```
Shell:   0x53480501, DDR_INFO 0x08551948, quiesce off
DDR top    cal SUCCESS, user reset released, quiesced 0
DDR bottom cal SUCCESS, user reset released, quiesced 0
Persona: window ID 0x00010101 (DDR test ABI 1, pattern walking one, address test)
```

| Test | Range | Result |
|------|-------|--------|
| Address test + walking one, top | 65 562 words (4.5 MiB) | 0 errors, 18 194 MB/s |
| Mailbox `poke top 0x1234 0xDEADBEEF` / `peek` | 1 word | 18 × `0xDEADBEEF`, matches |
| Inverted pattern, top | 524 288 words (36.0 MiB) | 0 errors, 18 170 MB/s |
| Full capacity, **both** channels | 33 554 458 words (2304.0 MiB each) | 0 errors, 18 169 MB/s |

The full run is 0.275 s of host time (0.133 s write + 0.132 s read per channel). 18.2 GB/s
per channel is close to the 19.2 GB/s the EMIF can carry at 1066.667 MHz with 576-bit
user data, so the test is not limited by the host or by the mailbox.

### Persona swap over PCIe

```
File:    shell_prbs.pr_partition.rbf (51132148 bytes)
SHA-256: 9300EAD3B2A1DBE14C5D8F511517D7B6F7BF28FBD954FD31092A8DB129FE4FE7
Result:  status 5 SUCCESS; data 30.522 s (1.60 MB/s)
PERSONA: 0x00040102 (id 0x0102)   <- was 0x0101
```

BAR0 and the link stayed at `0x383FFFE00000` / Gen3 x8, `ID 0x50434945` was still readable,
and the persona window changed to `0x00010102 (DDR test ABI 1, pattern PRBS-31)`.

The full PRBS-31 test then passed on both channels with seed `0x1234`:
33 554 432 words (2304.0 MiB) each, 0 error words, 18 169 MB/s write, 18 251 MB/s read.

> `fpga1768 load-pr` exits with code 4 and prints `Unknown persona ID 0x0102` after a
> successful load. That post-load check is the old project 03/04 `A+B` / `A-B` persona
> test and does not know the project 05 DDR personas; the PR load itself succeeded and
> `ddr status` / `ddr test` are the correct checks for this shell.

### Flash backup

```
flash-dump A  134217728 bytes, 191.9 s  SHA-256 4C727C311DD7FEDBF2B23522D1DCBF152A286645BE2B1D14680898962AA9326C
flash-dump B  134217728 bytes, 190.8 s  SHA-256 4C727C311DD7FEDBF2B23522D1DCBF152A286645BE2B1D14680898962AA9326C
erased (0xFF) 66881662 bytes (49.8 %)
```

Both runs are byte-identical, so the read path is stable and the backup is usable. The
dumps live outside the repository; they are not committed. Half the flash is erased,
which is consistent with the factory image occupying the lower part of the device.

### Die temperature

Without a fan the shell reached **130.2 °C** and the card shut down 78 s later (first
attempt the same day, see below). With a small fan the die sat at **47.7–49.0 °C** for the
whole session, including two 128 MB flash dumps:

| Phase | Temperature |
|---|---|
| idle after warm reboot | 47.7 °C |
| 5-minute idle sample, every 15 s | 48.3 °C, flat (19 samples, 47.7–48.3) |
| after walking-one full test | 48.3 °C |
| after `load-pr` (30 s of PR traffic) | 48.3 °C |
| during and after both flash dumps | 48.3–49.0 °C |

### Power estimate

`quartus_pow shell.qpf` reports 15.0 W total at Tj 75.5 °C:

| Block | Power |
|---|---|
| I/O (both DDR4 PHYs) | 6.20 W |
| Device static | 5.33 W |
| Transceivers (Gen3 x8) | 2.47 W |
| Core dynamic | 1.01 W |
| PLL + clock network | 0.83 W |
| Registers + combinational | 0.44 W |

The user logic is under 3 % of the total. The DDR4 PHYs, leakage and the PCIe SerDes are
94 %, which is why the board needs airflow even when no test is running.

## Result

**Success.** The shell builds, loads, enumerates at Gen3 x8 with a 64-bit BAR, both DDR4
channels calibrate, the full 2304 MiB of both channels passes the walking-one and PRBS-31
tests, the persona swaps over PCIe without touching JTAG or the memory calibration, and
two independent flash dumps match.

## Failures and limits seen the same day

- **Thermal shutdown without a fan.** The first attempt (no fan) read 130.2 °C and lost
  power 78 s later, about 20 minutes after AC power-on and 5 minutes after the shell was
  configured. No test ran in that attempt. A fan is mandatory.
- **Stuck `jtagserver`.** A killed `quartus_pgm` left `jtagserver` wedged; every later
  `quartus_pgm` hung with no progress and `jtagconfig` reported
  `Error when scanning hardware - Server error`. Killing the process as SYSTEM fixed it.
- **FT232H availability.** After an AC cycle the FT232H appears within a few minutes. On a
  boot where the factory image ran for 15 minutes it was absent from USB while the card
  was powered and enumerated on PCIe (`1414:B204`, Gen3 x8). That suggests the factory
  image disables the on-board programmer, but it is unproven and needs a dedicated run.
