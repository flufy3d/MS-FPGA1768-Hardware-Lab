# 2026-11-17 — PCIe BAR0 compute endpoint

- **Date:** 2026-11-17
- **Board:** Microsoft FPGA 1768 (Catapult v3 Longs Peak), PCB `M1003380-005`, no serial label
- **Host:** ASUS X99 (i7-5820K), Windows 10 x64 19045, card in a CPU PCIe slot at `02:00.0`
- **Toolchain:** Quartus Prime Pro 25.1.0.129, Platform Designer (`qsys`) installed,
  Programmer package, `jtag_hw_microsoft_catapult.dll`, `msftdi.cfg` at 5 MHz
- **Goal:** build a minimal PCIe #1 endpoint with a BAR0 register bank; the host writes
  two 32-bit operands and reads back `A + B`. No LEDs.

## What was done

1. Diagnosed the missing Platform Designer component. `qsys-generate` and `qsys-edit`
   failed with `ClassNotFoundException: com.altera.qsys.generate.QsysGenerate` because
   `<install>\qsys` did not exist. Installed the Quartus core/Platform Designer
   component from the full 25.1 installer; `qsys-generate` and `quartus_sh` then worked.
2. Created `projects/02_pcie_pio` with a Platform Designer Tcl generator, a
   SystemVerilog top level, SDC, QSF and README.
3. Built the Qsys system: Arria 10 PCIe hard IP, **Gen3 (8.0 Gbps) x8, 256-bit**,
   `Avalon-MM with DMA`, BAR0 64 KB, vendor/device `0x1172:0xE003`. Five 32-bit
   Avalon PIO instances at BAR0 offsets `0x00`, `0x10`, `0x20`, `0x30`, `0x40`.
4. Constrained `clk_100` (`AP20`), `clk_pcie1` (`AN29/AN28`, LVDS), `pcie1_perstn`
   (`AW16`), and PCIe #1 RX/TX lanes 0-7 from the pinout CSV.
5. Compiled with `quartus_sh --flow compile` (24m08s, timing met).
6. Programmed the `.sof` over JTAG (9m53s at 5 MHz).
7. Enumerated the endpoint with an elevated `pnputil /scan-devices`; read the link
   properties from Windows.
8. Attempted the BAR0 access test. BAR0 was unassigned after the hot scan; a device
   restart did not assign it.
9. The host bugchecked (`0x00000050`) during the BAR0 attempt. After the crash the
   card was no longer enumerated and the FT232H was gone.

## Observations

### Toolchain

The main Quartus install was missing the Platform Designer runtime. The symptom was:

```
qsys-generate --version
Error: Could not find or load main class com.altera.qsys.generate.QsysGenerate
```

The `qsys-generate.exe` launcher expects `QUARTUS_ROOTDIR/../qsys/lib` and
`QUARTUS_ROOTDIR/../qsys/bin`. After installing Platform Designer, `qsys-generate`
ran correctly and generated the HIP.

Critical warnings and disposition:

- `clk_100` is assigned to `CLKUSR` (`AP20`). The clock is 100 MHz, inside the
  100-125 MHz range the warning mentions; the HIP uses the dedicated `clk_pcie1`
  reference clock. Benign for this build.
- 40 unused RX and 40 unused TX channels. The design uses 8 of the 48 channels on
  PCIe #1; expected.

The fitter report shows the expected pin locations: `clk_100=AP20`,
`clk_pcie1=AN29/AN28`, `pcie1_perstn=AW16`, and the RX/TX lanes on the CSV pins.
No LED pins are used.

Windows link properties:

| `DEVPKEY_PciDevice_CurrentLinkWidth` | 8 |

The endpoint advertises Gen3 x8; the slot trained it at Gen2 x8, matching the
factory image's link. The HIP is alive and the PCIe link works.

### BAR0 state before the crash

Read with RWEverything's config-space commands (read-only):

```
02:00.0  0x00 = 0xE0031172   vendor/device
02:00.0  0x04 = 0x00100000   command 0x0000, status 0x0010
02:00.0  0x10 = 0x0000000C   BAR0 low: 64-bit prefetchable, base 0
02:00.0  0x14 = 0x00000000   BAR0 high
```

BAR0 was **not assigned** after the hot PnP scan, and the command register had
memory space disabled. `pnputil /restart-device` restarted the device successfully
but did not allocate a BAR.

### Host crash and current card state

At 22:00:32 Windows bugchecked:

```
Bugcheck 0x00000050  PAGE_FAULT_IN_NONPAGED_AREA
dump: C:\Windows\MEMORY.DMP
```

The crash happened during the BAR0 attempt. The most likely cause is a write
through RWEverything's kernel driver to an unassigned BAR0 (base 0), which lands
near physical address 0. This is a host-side tool error, not a proven FPGA fault.
The session history was lost with the crash, so the exact command is not recorded.

After the crash and reboot:

- `02:00.0` config space reads all `0xFFFFFFFF`; no `1172` or `1414` device.
- The two `USB\VID_0403&PID_6014` devices are `Present=False` /
  `CM_PROB_PHANTOM`; the FT232H is not on USB.
- `jtagconfig` reports `No JTAG hardware available`.
- USB controllers report no errors.

The card is unpowered or its power/FT232H latched off. A warm reboot does not
restore PCIe slot or auxiliary 12 V power. A full AC power cycle is required.
The user will bring a smart power controller on 2026-11-18.

## Result

**Partial.**

- The project builds, timing is met, the bitstream loads, and the endpoint
  enumerates at `1172:E003` with a Gen2 x8 link (max Gen3 x8).
- The BAR0 compute test was **not completed**. BAR0 was unassigned after the hot
  scan; the host crashed during the BAR0 attempt; the card then lost power.
- The configuration flash was not written.
