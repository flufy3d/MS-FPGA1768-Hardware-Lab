# 03 — PCIe Gen3 x8 endpoint with BAR0 registers and a die temperature register

The Gen3 x8 follow-up to [02_pcie_pio](../02_pcie_pio/). Same `A + B` register bank on
BAR0, but the hard IP runs **Gen3 x8 (256-bit)** with a **64-bit prefetchable BAR0**, and
one extra register returns the Arria 10 die temperature. No LEDs are used.

| Item | Value |
|------|-------|
| Top-level entity | `pcie_gen3` |
| Device | `10AXF40AA` (Arria 10) |
| PCIe | #1, Gen3 (8.0 GT/s) x8 |
| Hard IP | Arria 10 PCIe HIP, Avalon-MM with DMA (external descriptor controller, DMA unused), 256-bit |
| BAR0 | 64-bit prefetchable memory, 64 KB; BAR1–BAR5 disabled |
| Vendor / device ID | `0x1172` / `0xE003` (same as project 02, same Windows driver) |
| Configuration | volatile `.sof` over JTAG, config flash untouched |
| Status | sources **verified on hardware 2026-11-18** (PCB `M1003380-005`) as built before the rename to `pcie_gen3`; the renamed project in this directory has its IP generated but is **not yet compiled or tested on hardware** |

## Purpose

1. Prove that the card and a lab-built bitstream train **Gen3 x8**.
2. Prove 32-bit MMIO through a **64-bit BAR above 4 GB**.
3. Give the host a way to read the **FPGA die temperature**, because this card overheats
   without airflow (see "Thermal warning").

## Host requirements

These were needed on the lab host (ASUS X99-E, BIOS 1801); other boards may differ.

- BIOS PCIe link speed set to **Gen3** (Auto gave Gen2 on this board).
- **Above 4G Decoding** enabled.
- **Warm reboot after loading the `.sof`.** The 64-bit BAR is assigned only when the
  device is present at boot; after a hot `pnputil /scan-devices` the device stays at
  problem code 10. The FPGA keeps its volatile configuration across a warm reboot.
- The test driver from [`../02_pcie_pio/driver`](../02_pcie_pio/driver/) (test signing,
  Secure Boot off).

If the host cannot meet these, use project 02 (Gen2 x8, 32-bit BAR, works after a hot scan).

## Register map

Six 32-bit Avalon PIO instances, 16 bytes apart, plus a scratch RAM.

| Offset | Name | Access | Description |
|--------|------|--------|-------------|
| `0x00` | `A` | RW | Operand A |
| `0x10` | `B` | RW | Operand B |
| `0x20` | `SUM` | RO | `A + B`, 32-bit, wraps on overflow |
| `0x30` | `COUNTER` | RO | Free-running 100 MHz counter |
| `0x40` | `ID` | RO | `0x50434945` |
| `0x50` | `TEMP` | RO | Die temperature sensor, see below |
| `0x8000`–`0xFFFF` | scratch RAM | RW | 32 KB on-chip RAM, not initialised; sizes BAR0 to 64 KB |

`TEMP` fields:

| Bits | Meaning |
|------|---------|
| `[9:0]` | sensor code latched at the end of the last conversion |
| `[25:16]` | raw sensor output, sampled continuously |
| `[27]` | end-of-conversion level |
| `[31:28]` | conversion counter (low 4 bits); it must change between reads about 0.2 s apart |

`degrees C = code * 693 / 1024 - 265` (vendor formula for the Arria 10 sensor; status
`reported` — not cross-checked against another thermometer on this card).

## Pins used

Same as project 02; all locations and I/O standards are in `pcie_gen3.qsf`.

| Signal | Pin(s) | Notes |
|--------|--------|-------|
| `clk_100` | `AP20` | 100 MHz board oscillator, register bank clock |
| `clk_pcie1` | `AN29` / `AN28` | 100 MHz PCIe #1 reference clock |
| `pcie1_perstn` | `AW16` | PCIe #1 PERST# |
| `pcie1_rx[7:0]`, `pcie1_tx[7:0]` | see `.qsf` | edge connector lanes 0–7 |

## Qsys system

`pcie_gen3_sys.qsys` and `ip/pcie_gen3_sys/*.ip` are generated by `make_qsys.tcl`:

- `interface_type_hwtcl = "Avalon-MM with DMA"`, `wrala_hwtcl = 0` (Gen3 x8, 256-bit).
  Plain Avalon-MM offers Gen3 only up to x4. DMA mode forces BAR0 to 64-bit prefetchable.
- `internal_controller_hwtcl = 0`. With the internal DMA descriptor controller the HIP has
  **no `rxm_bar0`** and BAR0 belongs to the controller; with it off, `rxm_bar0` drives the
  register bank. `select_design_example_hwtcl = "DMA"` is required or generation fails.
  The DMA streams (`rd_ast_*`, `wr_ast_*`) and masters (`dma_rd_master`, `dma_wr_master`)
  are unconnected; DMA is not usable in this design.
- `bar2_type_hwtcl = "Disabled"`. The 2026-11-17 design left a 64-bit BAR2 enabled with
  nothing behind it and never started on Windows.
- BAR0 size follows the address span behind `rxm_bar0`; the scratch RAM makes it 64 KB.
- `altera_temp_sense` (Arria 10 temperature sensing diode, internal 1 MHz clock). Its
  `tempout`/`eoc` are sampled in `clk_100` through synchronisers in `pcie_gen3.sv`; the two
  `set_false_path` lines in `pcie_gen3.sdc` cover that asynchronous crossing.

Regenerate:

```powershell
. ..\..\scripts\env.ps1
Remove-Item -Recurse -Force ip\pcie_gen3_sys, pcie_gen3_sys   # else save_system writes *_1.ip variants
& "$env:QUARTUS_ROOTDIR\..\qsys\bin\qsys-script.exe" --script=make_qsys.tcl --quartus-project=pcie_gen3.qpf
quartus_ipgenerate pcie_gen3 -c pcie_gen3 --run_default_mode_op
```

## Build

```powershell
. ..\..\scripts\env.ps1
..\..\scripts\build.ps1 -Project pcie_gen3.qpf
```

About 21 minutes on the lab machine.

## Program and test

```powershell
. ..\..\scripts\env.ps1
quartus_pgm -m jtag -o "p;output_files\pcie_gen3.sof"   # about 9 minutes at 5 MHz TCK
shutdown /r /t 0                                        # warm reboot, see Host requirements
# after the reboot:
..\02_pcie_pio\user\build\pcie_bar_test.exe --write     # A + B test
..\02_pcie_pio\user\build\pcie_bar_test.exe --temp 5    # die temperature every 5 s
```

This is a volatile JTAG load. **Do not write the configuration flash.** A power cycle
restores the factory Microsoft image (`1414:B204`).

## Expected observation

```
IDs:    1172:E003
BAR0:   0x383FFFE00000 length 0x10000 mapped=1      (address varies; above 4 GB)
ID:     0x50434945
Writing A=0x12345678, B=0x11111111 ...
SUM:    0x23456789 (expected 0x23456789)
A+B test PASSED.
```

`DEVPKEY_PciDevice_CurrentLinkSpeed` = 3, `CurrentLinkWidth` = 8, problem code 0.

## Thermal warning

Measured 2026-11-18 in a desktop slot with the passive heatsink and **no fan**: the die read
86 °C 19 minutes after power-on and 101 °C after 28.5 minutes (about 1.4 °C per minute),
with only this endpoint running. In an earlier run the card lost power 36 minutes after
power-on. Fit a fan before powering the card for more than a few minutes, and watch
`--temp`. This design only reports the temperature; it does not protect the card.
