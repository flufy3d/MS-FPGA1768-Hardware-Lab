# 02 — PCIe BAR0 compute endpoint

Minimal Arria 10 PCIe #1 endpoint with a BAR0 register bank. The host writes two
32-bit operands and reads back their sum. A free-running counter and an ID register
prove that the read path is real. **No LEDs are used** — project 01 already verified
the LED pins, and this project is about BAR0 MMIO and FPGA-side computation.

| Item | Value |
|------|-------|
| Top-level entity | `pcie_pio` |
| Device | `10AXF40AA` (Arria 10) |
| PCIe | #1, x8, Gen3-capable (trains Gen2 x8 on the lab slot) |
| Hard IP | Arria 10 PCIe HIP, Avalon-MM with DMA, 256-bit, BAR0 64 KB |
| Vendor / device ID | `0x1172` / `0xE003` |
| Configuration | volatile `.sof` over JTAG, config flash untouched |
| Status | built, timing met, enumerated; BAR0 compute test pending |

## Purpose

The design proves three things in one step:

1. The PCIe hard IP trains and the host enumerates the endpoint.
2. The host can perform 32-bit MMIO reads and writes through BAR0.
3. The FPGA actually computes the returned value (`A + B`), rather than looping
   back a host-written register.

## Register map

The register bank is built from five 32-bit Altera Avalon PIO instances. A PIO
slave occupies 16 bytes, so the registers are 0x10 apart.

| Offset | Name | Access | Description |
|--------|------|--------|-------------|
| `0x00` | `A` | RW | Operand A |
| `0x10` | `B` | RW | Operand B |
| `0x20` | `SUM` | RO | `A + B`, 32-bit, wraps on overflow |
| `0x30` | `COUNTER` | RO | Free-running 100 MHz counter |
| `0x40` | `ID` | RO | `0x50434945` |

`A` and `B` are write-only from the host's point of view (the PIO is an output
register). The correct `SUM` proves both writes arrived. `COUNTER` changes between
two reads; `ID` is constant.

## Qsys system

`pcie_pio_sys.qsys` is generated by `make_qsys.tcl`:

- Arria 10 PCIe hard IP, `lane_rate_hwtcl = Gen3 (8.0 Gbps)`,
  `wrala_hwtcl = 0` (Gen3 x8, 256-bit).
- `interface_type_hwtcl = Avalon-MM with DMA`. The DMA engine is unused; only the
  BAR0 Avalon-MM master (`rxm_bar0`) is connected, to the PIO bank. The Gen3 x8
  256-bit HIP mode is not available with the plain Avalon-MM interface.
- BAR0 is 64 KB, 64-bit prefetchable memory.
- Vendor/device ID `0x1172:0xE003` (Altera development-kit IDs) so the Altera PCI
  API driver can match it if one is installed later. Change these in
  `make_qsys.tcl` if you need a unique ID.
- A 100 MHz clock source drives the PIO bank; the HIP reference clock is the
  dedicated `clk_pcie1` input.

The upstream `PCIe1` reference design uses `wrala_hwtcl = 7` (Gen2 x8, 128-bit).
This project deliberately uses the Gen3 x8 256-bit mode instead.


Or directly:

```powershell
quartus_sh --flow compile pcie_pio.qpf -c pcie_pio
```

The first build of the PCIe HIP takes about 24 minutes on this machine. The
resulting `.sof` is about 36 MB.

## Program

```powershell
..\..\scripts\program.ps1 -Sof output_files\pcie_pio.sof
```

This is a volatile JTAG load. **Do not write the configuration flash.** A power
cycle restores the factory Microsoft image (`1414:B204`).

## Host-side test

### Linux (recommended)

Bind the endpoint to `vfio-pci` or use `uio_pci_generic`, enable memory space, and
use `pcimem`:

```bash
sudo lspci -nn | grep 1172
sudo setpci -s 02:00.0 COMMAND=0x6
sudo pcimem /sys/bus/pci/devices/0000:02:00.0/resource0 0x00 w 0x12345678
sudo pcimem /sys/bus/pci/devices/0000:02:00.0/resource0 0x10 w 0x11111111
sudo pcimem /sys/bus/pci/devices/0000:02:00.0/resource0 0x20 r
# expect 0x23456789
sudo pcimem /sys/bus/pci/devices/0000:02:00.0/resource0 0x40 r
# expect 0x50434945
```

Read `0x30` twice; the counter must change.

### Windows

Windows has no in-box user-mode BAR mapping. Do **not** write BAR0 until the
device has a valid, non-zero BAR address and memory space is enabled. In this lab,
writing an unassigned BAR0 through RWEverything caused a host bugcheck
(`0x00000050`). If you use RWEverything, read the config space first and confirm:

- command register (`0x04`) has memory space enable set;
- BAR0 (`0x10`/`0x14`) contains a real base address, not `0x0000000C`.

A Linux live USB with `pcimem` is the safer path.

## Expected observation

| Write | Value |
|-------|-------|
| `A` at `0x00` | `0x12345678` |
| `B` at `0x10` | `0x11111111` |
| `SUM` at `0x20` | `0x23456789` |
| `ID` at `0x40` | `0x50434945` |

Wrap test: `A = 0xFFFFFFFF`, `B = 0x00000001` → `SUM = 0x00000000`.

## Notes

- The card is in an x8 slot, so only PCIe #1 (lanes 0-7) can train.
- The endpoint advertises Gen3 x8; this slot trained it at Gen2 x8, the same as
  the factory Microsoft image. Check `LnkCap` vs `LnkSta` before blaming the design.
- The `.sof` is not committed. Rebuild it or use the SHA-256 above.
- If JTAG reads `0xFFFFFFFF` after a crashed programmer session, power off at the
  PSU. A Windows reboot and `FT_CyclePort` do not clear the FT232H latch.
