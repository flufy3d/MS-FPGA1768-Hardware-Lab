# 04 — DDR4 bring-up

> Status: unknown — built, not yet tested on hardware in this lab (calibration reported by prior art)
> Source: [docs/hardware/ddr4.md](../hardware/ddr4.md), [projects/05_shell](../../projects/05_shell/)
> Last verified: 2026-11-19 (build only)

## Goal

Calibrate both DDR4 channels and run a memory test from the FPGA, with the results read
over PCIe.

## Design

[projects/05_shell](../../projects/05_shell/): the PCIe shell (project 04's Gen3 x8
endpoint and PR controller) plus both EMIF channels at DDR4-2133, 72 bit, ECC off. The
memory tests are PR personas, so a different test algorithm is loaded over PCIe without
JTAG:

| Persona | Test |
|---------|------|
| `persona_walk` (base image) | address-line test + walking one / walking zero over the selected range |
| `persona_prbs` | PRBS-31 write/read over the selected range |

The community [DDR4_Dual](https://github.com/tow3rs/catapult-v3-smartnic-re) project
(`Projects/DDR4/DDR4_Dual`, Quartus 20.1) is the source of the EMIF parameters. It is
**referenced, not copied**: `make_qsys.tcl` sets the same parameters in a script and names
the source (AGENTS.md section 13).

## Steps

1. Build: see the project README (`make_qsys.tcl`, then `build_pr.ps1`).
2. Read the die temperature; the card needs airflow for anything longer than a few
   minutes (see [power.md](../hardware/power.md)).
3. Program `shell.sof` over JTAG (volatile), then warm-reboot so that the 64-bit BAR0 is
   assigned.
4. `fpga1768 ddr status`: both channels must show `cal SUCCESS` and the user reset
   released. LEDs: `led[0]` top calibrated, `led[1]` bottom calibrated, `led[2]`
   calibration failed, `led[3]` heartbeat.
5. Short test first: `fpga1768 ddr test --ch top --end 0xFFFF` (4.5 MiB), then the whole
   channel, then both channels.
6. Load the other persona with `fpga1768 load-pr …shell_prbs.pr_partition.rbf` and test
   again.

## What success proves

- Both DDR4 channels are populated and wired correctly, including the ECC byte lane.
- The reference clocks, OCT resistors and EMIF parameters work on this board.
- Every address line works (address test) and every data line toggles both ways (walking
  one / zero, PRBS).

## If calibration fails

| Symptom | Likely cause |
|---------|--------------|
| `cal FAIL` on both channels immediately | `oct_rzqin` not on `L2`/`AH7`, wrong refclk pins, DDR4 rails missing |
| Calibration fails after a while, or margins are small | board-skew parameters (the reference values are IP defaults, not measurements, see [ddr4.md](../hardware/ddr4.md)) |
| One channel only | that channel's rail or one DRAM device |
| Calibrates but data errors | timing margin or a bad lane; the test reports the DQ lane mask and the first failing word. Lower the speed only as a diagnostic: with the 266.667 MHz reference clocks the EMIF IP offers no other memory frequency at quarter rate (2026-11-19), so a slower test needs a different PLL setup |
| Errors only on bits 64–71 of each beat | the ECC byte lane (U6/U11 lower byte) |

## Notes

- Usable memory per channel is 2.25 GiB with ECC off (72-bit words), 2 GiB of data with ECC
  on. All 2²⁵ word addresses exist; there is no unusable address range.
- The Arria 10 EMIF calibration is temperature sensitive; test cold and warm.
